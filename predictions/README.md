# MiroFish — Example Predictions

This folder contains end-to-end runs of the MiroFish multi-agent simulation pipeline on two
real-world scenarios. Each run produced a qualitative prediction report from the full 5-stage
pipeline (Ontology → GraphRAG → Env Setup → Dual-World Simulation → Report Generation).

> **Important:** MiroFish is a **social-dynamics simulation engine, not a polling/forecasting
> system**. The reports are emergent narratives produced by LLM-driven agents seeded with real
> context — **not statistically validated forecasts**. Neither report names a single numeric
> winner; each converges on a *structural* prediction. Treat these as demonstrations of the
> engine's capability, not as electoral predictions.

## Scenarios

| Scenario | Folder | Mechanism | What it predicts |
|----------|--------|-----------|------------------|
| Colombia 2026 presidential election | [`colombia-presidential-2026/`](colombia-presidential-2026/) | Popular vote (1st round May 31 2026) | A highly polarized two-bloc race (left vs. radical right) with many undecideds; social media as decisive battleground |
| Universidad de Antioquia 2026–2029 rector | [`udea-rectoria-2026/`](udea-rectoria-2026/) | **Designation by the Consejo Superior Universitario (CSU)**, not popular vote | A process-centric narrative: CSU values, faculty influence, candidate expectations (digital education, financial sustainability, autonomy vs. MEN), risks of polarization/misinformation |

## Contents of each folder

- `reality-seed.txt` — the unstructured Reality Seed used to initialize the simulation.
- `full_report.md` — the prediction report generated by the MiroFish ReportAgent.
- `test-report.md` — end-to-end test report documenting all 5 stages (pass/fail, counts, evidence).
- `report_final.png` — screenshot of the completed report in the UI.

## How these were produced

Each run used the live local stack (`npm run dev`) with real OpenAI (`gpt-4o-mini`) + Zep Cloud
keys, configured temporarily and then removed (no real keys are stored in this repo). Round counts
were reduced from the 72h default to keep runs manageable. See each `test-report.md` for per-stage
HTTP results, node/edge counts, agent counts, and event counts.
